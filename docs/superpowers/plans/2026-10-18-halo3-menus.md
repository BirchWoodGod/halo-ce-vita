# Halo 3-style Menus Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a Halo 3-style menu set (main menu, campaign lobby, settings look), drawn over Halo CE's animated ring and selectable with a Menu style setting. The first testable slice is the main menu.

**Architecture:**
- The Halo 3 screens are a second set of OpenCE-format XML screens plus our own PNG art.
- `menu_tags.c` builds them into Halo CE widget tags when ui.map loads, exactly as it already does for the OpenCE multiplayer screens.
- `menu_tags_screen` opens them in place of the Xbox screens they replace while Menu style is Halo 3.
- The settings panel keeps its rows and gets a second drawing path in the GXM overlay.

**Tech Stack:** C89 (game and port), OpenCE menu XML (`menu_files.c`, `menu_tags.c`, `menu_functions.c`), Python 3 + Pillow 12 for the art generator, the Linux harness (`build/linux/halo`), and bash tests in `port/vita/tests/`.

**Spec:** `docs/superpowers/specs/2026-10-18-halo3-menus-design.md`

## Global Constraints

- The background stays Halo CE's animated ring: ui.map's main-menu scene is never replaced or covered by a full-screen opaque image.
- No Bungie, Microsoft or Halo Online art, fonts or text in the repo. Our own PNGs only, plus a free font with its licence file beside it.
- Menu style = Halo CE (`classic`) behaves exactly as dev-1.1.1. All existing `run_menus_test.sh` cases pass unchanged.
- The Halo 3 set needs no Halo PC files (bitmaps.map/loc.map). It uses only `port/vita/app0/menus/halo3/` and ui.map.
- A Halo 3 PNG is RGBA8, not interlaced, at most 512 KB (`MAXIMUM_PNG_BYTES`), and has power-of-two-friendly sizes where the widget scales it.
- Pictures load when a screen first opens, not when ui.map loads.
- Every new string goes through `T()` and gets a line in `port/vita/app0/lang/es.txt`.
- Commits end with the session's Co-Authored-By and Claude-Session trailers.

## Review Focus

1. **Menu style changed in the settings panel while a Halo 3 screen is open.** The open screen stays until it's closed, and the next open uses the new style, with no crash and no "is not a tag index". Test: Task 2 `h3style` case.
2. **A Halo 3 PNG is missing or broken.** That screen falls back to the Xbox one, with a log line and no crash. Test: Task 2 `h3broken` case.
3. **Coming back from a level (Quit to Main Menu)** lands on the Halo 3 main menu again, after ui.map's tags are rebuilt. Test: Task 4 `h3level` case.
4. **No Halo PC files.** The Halo 3 main menu still opens, and Multiplayer opens the Xbox screen. Test: Task 4 `h3xbox` case.
5. **Spanish.** Every Halo 3 string fits its widget. Test: Task 4 runs `h3main` with `HALO_LANGUAGE=es` and checks the log has no "text clipped" line, which Task 2 adds.

### Task 2: A second menu set, independent of the Halo PC files

**Files:**

- Modify: `port/linux/game/menu_tags.c`
- Create: `port/vita/app0/menus/halo3/menus.txt`, `port/vita/app0/menus/halo3/README.txt`

- Modify: `port/vita/tests/run_menus_test.sh`

**Interfaces:**
- Consumes: `halo_menu_style_halo3()` (Task 1).
- Produces:
  - `struct halo_menus const *halo_menus_load_set(char const *folder)`. `folder` is `"menus"` (today's set) or `"menus/halo3"`. `halo_menus_load()` becomes `halo_menus_load_set("menus")`.
  - XML: `<menus root="..." replaces="<xbox screen tag path>">`. Each file's root may name the Xbox screen it stands in for, and a set may hold several.
  - Our tags are named under the prefix `h3\` (as `pc\` is today). `boolean h3_menu_tag(long tag_index)`.
  - `menu_tags_screen(tag)` behaves as follows:
    - for a tag some Halo 3 file replaces: it returns that file's root tag when `halo_menu_style_halo3()` is 1 and the set's art loaded (art loads on first open, as `menu_tags_art_load` does for the PC set); otherwise it returns `tag`;
    - the PC set's own mapping (`XBOX_MULTIPLAYER_SCREEN`) is unchanged and is checked after the Halo 3 one.
  - Log lines: `menus: Halo 3 set: %ld widgets, %ld pictures` at build; `menus: Halo 3 screen %s for %s` when one opens; `menus: Halo 3 set left out: %s` on any failure. When a text widget's string is wider than the widget: `menus: text clipped in %s`.
